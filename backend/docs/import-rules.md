# Import rules

1. **Strict layers:** HTTP → session → submission_cycle → submission → state → pure rules. Pure modules never import session, state, or HTTP.
2. **Shared:** any layer may import Pydantic types from `models.py` and play-mode policy from `play_mode.py`.
3. `navigation_snapshot` **reads only for snapshot/view:** may read `SessionState` from `models.py`; must not mutate state or call session use-cases when building snapshots or views. View payload is derived from data captured on the snapshot at construction time; a snapshot answers for the state as it stood when built, so a use-case that mutates state builds a fresh one rather than reusing the earlier value (ADR-0003). `navigation_resolve` **does not mutate session state either:** it validates and resolves a navigation intent into a target against a `navigation_snapshot.NavigationSnapshot`, reading `NavigationSnapshot`/`ChapterNavigationContext` one-directionally (resolution depends on the snapshot it validates against, never the reverse) and never calling session use-cases.
4. `session.py` **owns the response view:** `respond()` builds `SessionResponse` from persisted `SessionState` plus play mode and navigation; calls state helpers and `navigation.build_*`; does not embed view-building logic beyond assembling the payload.
5. `Curriculum` **is injected below session:** modules below the session use-case layer receive `Curriculum` as a parameter; only HTTP/session resolve it via `resolve_curriculum()`.
