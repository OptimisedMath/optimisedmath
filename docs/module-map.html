Architecture reference

Where things live, and why

A map of the Optimised Math Learning monorepo — a Polish maths practice app for klasy 4–8. FastAPI owns game rules and state; Next.js owns presentation. This doc traces the seams between them, the layers inside the backend, and the modules on both sides.

FastAPI · Python Next.js App Router · TypeScript SQLite persistence YAML curriculum pytest · Vitest

Every rule outcome (grading, streak, XP, Flawless, Locked/Reachable, input mode) is computed once, in the backend, and travels to the frontend as a payload field — see ADR-0002. The frontend never re-derives a rule; it maps payload fields to pixels.

Core response shapes

SessionState
Persisted Session: identity, progression (xp, streak, flawless), selection, submission-cycle flags, Frontier map, problem plumbing. Lives server-side only.
SessionResponse
Wire payload built by SessionResponse.from_state(): persisted fields plus derived view fields (can_submit, can_next_problem, streak_meter, admin_mode, navigation).
NavigationView
Computed navigation state attached to every SessionResponse: available chapters/topics/levels, completion meters, radio_only, has_next_unlocked_topic.
ProblemResponse / SubmissionResponse
Next-problem payload (problem + state) and grading outcome (state + is_correct + feedback) respectively.

Seams & import rules

The rules that keep the layered architecture from collapsing into a ball of imports.

Strict layers

HTTP → session → submission_cycle → submission → state → pure rules. Pure modules never import session, state, or HTTP.

Shared exceptions

Any layer may import Pydantic types from models.py and play-mode policy from play_mode.py.

Navigation reads only

navigation_snapshot reads SessionState for snapshot/view only — never mutates state or calls session use-cases. navigation_resolve validates against the snapshot one-directionally.

session.py owns the response view

respond() builds SessionResponse from persisted state plus play mode and navigation. It calls state helpers and navigation.build_* — it doesn't embed view logic beyond assembling the payload.

Curriculum is injected below session

Only HTTP/session resolve Curriculum via resolve_curriculum(); everything below receives it as a parameter.

Cycle-field clearing has one owner

session_state.clear_submission_cycle_fields is the sole owner of resetting streak/feedback/problem/input-mode. Called directly by navigate_to, load_profile, and hard_reset — no forwarding wrapper in between.

Frontend session boundary

All arena/login session state lives in lib/session/. Import via @/lib/session; nothing else calls session APIs or touches session localStorage.

Architectural decisions

ADR-0002 — Backend owns game rules

FastAPI owns authoritative game state and rule outcomes: grading, streak, XP, Flawless, input mode, Locked/Reachable. Next.js owns presentation and payload→UI mapping — not a second rules engine. The leak test: a formula that would have to exist in both Python and TypeScript. Mapping feedback_type into a phase, or streak_meter into stars, is fine.

ADR-0001 — English codebase, Polish UI

Engineering vocabulary stays English throughout code, types, and internal docs. Polish appears only in user-facing copy — UI labels, feedback messages, curriculum names, and one-line pedagogical docstrings on topic_*.py generators. No Polish synonyms as alternate code names (e.g. no passa alongside streak).

Glossary snapshot

A handful of terms that recur across every module above. Full glossary: CONTEXT.md.

Frontier
The furthest Topic/Level a Student has earned in a Chapter — persisted per chapter. Defines Locked vs Reachable.
Streak
Consecutive correct answers at the current Level. Resets on a penalized mistake, level completion, or navigating away.
Mastery
Streak reaching the Mastery threshold (3) while playing At the Frontier — triggers Level completion.
Flawless
Reaching the current Level without a penalized mistake since the last streak reset. Earns bonus XP on Level completion.
Trap / Wrong / Soft Error
Trap: misconception-targeted wrong answer. Wrong: generic calculation slip. Soft Error: format issue that doesn't penalize streak.
Submission cycle
One Problem lifecycle: served → answered (Submission) → Feedback → Next problem. Navigation or Next problem starts a fresh cycle.
Admin mode
QA/debug play mode for designated Usernames: full effective unlock, never writes XP/Flawless/Frontier. Invisible to Students.
Radio / Input mode
Radio: four-option ABCD, active at streak 0 or on radio-only Topics. Input: free-text entry once streak ≥ 1.
