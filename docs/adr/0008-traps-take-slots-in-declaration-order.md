# A Problem offers its first valid Traps in declaration order

A Level may author more Traps than a Problem has slots for. A Trap that cannot be offered on one draw — negative where negatives are not allowed (ADR-0007), colliding with an option already taken, or passed as `None` — leaves a slot a later Trap can fill with a real error instead of a Filler. We decided that `build_problem_dict` fills the slots from a template's Traps **in the order the template passes them**, taking the first three that can be offered (#266). A slot no later Trap fills goes to a Filler, whether a collision or a skipped Trap freed it (amended by ADR-0009, which also sets how Fillers are made). Comparison Levels, whose options are the symbols `<`, `>` and `=`, are untouched.

**The order is believed rules first, then slips.** A Trap that references a Misconception ranks above one that does not, because Misconceptions are what telemetry aggregates and a Deconstruction is built against; when only three fit, they are the ones worth the slot. The order lives in each template's `traps` dict, not in `@declares_traps`, which is the union across a generator's templates and carries no per-template order.

**Considered options:** A random three of the valid Traps per roll, as #277 first specified for `Potęgowanie` Level 2 (rejected — it varies the distractors, but serves a Misconception Trap on fewer draws even when it is valid, and makes which options a Problem shows unpredictable from its code); each generator swapping in a named reserve with its own conditional (rejected — the same branch repeated per template, and nothing stops the reserve colliding in turn); ordering by how common each error is (rejected for now — there is no telemetry to rank by before launch).

**Consequences:** A Trap ranked beyond the slots is served only on draws where an earlier one cannot be. The trap-slug sweep still requires every declared slug to be reachable, so a Trap whose predecessors are valid on every draw can never be served, and ranking it there is an authoring error the sweep will catch. "Fewer Traps than slots" is no longer a property of a Level but of one Problem, and the Filler entry in `CONTEXT.md` says so.
