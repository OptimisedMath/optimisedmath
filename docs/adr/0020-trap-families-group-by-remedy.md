# Trap families group Traps by remedy, not by believed rule

The catalogue a Trap points into was defined as a set of **believed rules** (Misconceptions), and was also the unit a Deconstruction's hit count keys on. The two jobs pull apart: two different wrong rules are often fixed by one walkthrough (`borrows_ten_instead_of_the_denominator` and `subtracts_the_fractions_in_reverse_to_avoid_borrowing` both need "rozmień jedną całość na tyle części, ile wynosi mianownik"), so splitting by rule stopped hits adding up, and the believed-rule analysis (#406) cost real work for text nothing read — the catalogue's `explanation:` was never shown, and 51 of 57 entries had no walkthrough. **Decision:** a Trap points at a **Trap family** — the Traps one Deconstruction would fix, whether or not it has been written. The family replaces "Misconception" as the concept and the word. Slips still join no family.

**Why keep a catalogue at all, rather than map Traps straight to the six written walkthroughs:** the families without a walkthrough are the grouping work already done for the next one, and family-level hit telemetry ranks which walkthrough to build next. A Trap mapped to nothing until a walkthrough exists leaves both to a Curriculum-wide sweep each time.

**Considered options:** keep believed rules and let several rules share one walkthrough, moving the hit count to the walkthrough (rejected — it keeps the analysis this decision exists to drop, for per-rule prose nothing displays); keep "Misconception" as the word with a loosened definition (rejected — the word means one wrong belief, and a future reader would re-run the believed-rule audit from it).

**How coarse.** A walkthrough is one function of the Problem's `parameters`; it cannot adapt to the Student's answers, but it may take a different path for a different Problem shape, as `ignores_the_order_of_operations` already does. A family is therefore as coarse as **one walkthrough teaching one idea** allows — "ułamek z liczby to mnożenie przez ten ułamek" covers both `⅔ z liczby 6` and `Znajdź liczbę, której ⅗ wynosi 12`, run forwards or backwards. The aim is few walkthroughs, each catching many Traps. The one-idea bound is what stops it sliding into one family per Topic, which would leave telemetry unable to rank what to build and let two unrelated slips of attention fire a walkthrough.

**Consequences:** the membership test is the old split rule promoted to the definition — "would one walkthrough, teaching one idea, fix every Trap in this family?" — so names like `mishandles_converting_units` are sound family names rather than slips of naming. ADR-0014 is unchanged: the count still keys on the catalogue slug, now a family's. A family may point at a walkthrough that cannot yet render every Problem its Traps come from. The Deconstruction is then skipped for those Problems, and the gap is recorded as an expected failure in `tests/test_deconstruction_contracts.py` that names the issue extending the walkthrough, so the skip stays visible rather than silent.
