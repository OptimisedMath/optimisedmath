# The number line is a second renderer on a shared Canvas, not a scene Figure

The scene renderer (`backend/core/scene/`, #211) draws Geometria figures from maths so a label cannot contradict its drawing; `generate_universal_number_line` in `core/utils.py` was the one drawing that did the opposite — caller-typed label strings, a hardcoded 4000×900 frame, and dark-mode-only colours that vanish on the light theme. We decided the number line moves to its own module, `scene/numberline.py`, built on a `Canvas` extracted from the scene's render context: the figure-free part — stroke and text emit, the whole-scene label placement pass, and the viewBox derived from the content bounding box. The scene's `Ctx` extends `Canvas` with the `Figure` and its polygon rules. Tick labels are derived from a `Fraction` start and step and printed exactly with `fmt_dec`, so a number line that disagrees with its own labels is not writable either (#280).

**Considered options:** One more constructor inside the scene (rejected — `Figure` is a CCW polygon or a circle; a 1-D axis would need a third kind, special cases in the pen-unit and outward-normal rules, and a `Target` annotation in the shared vocabulary with a single caller); keeping the function in `utils.py` with only the colour and label fixes (rejected — two renderers that share no code drift, and the number line would reimplement label placement and viewBox derivation by hand); building a scene `Ctx` around a dummy `Figure` (rejected — the polygon methods stay callable on a figure that has none).

**Consequences:** The target marker — the glowing accent pointer at the answer — belongs to `numberline.py` and nowhere else. A future 1-D drawing (a bar model, a thermometer) builds on `Canvas` beside it rather than bending `Figure`. The number line's font is capped so labels never stagger onto a second row, since the scene's default size overlaps labels on adjacent ticks. The cap is measured against the nearest pair of labelled ticks, not every tick gap: over every distinct draw of the ten number-line generators neither rule staggered, but capping against every tick gap shrank all of Topic 30 L2, L5 and L6 to 12–16 px where the labelled-pair cap kept them near 19 px — against 9.2 px from the old renderer (prototype on branch `prototype/280-number-line`).
