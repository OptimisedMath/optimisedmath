# Conversion-aware unit grading, with a grader-synthesized units Trap

Geometria Topics ask for answers that carry a Unit (`24 cm²`). Grading compares the Unit's **dimension** first, then converts same-dimension units to the Problem's `expected_unit` before comparing magnitudes — so `0,0024 m²` is Correct for `24 cm²`. Where the converted value is wrong but the raw number is right (`24 m²`), the grader **synthesizes** a Trap on `converts_units_incorrectly` rather than requiring the generator to author every wrong unit.

**Decision:** A Problem carries `expected_unit` (a length or area unit) separate from `grading_policy` — the two are orthogonal axes, notation-strictness and dimension. Splitting and normalizing the Unit happens in `grade()` *above* `parse_to_fraction`, never inside it. Omitting a Unit where one is expected is **Wrong**, not a Soft Error: on these Topics the Unit is part of the answer, exactly as form is on exact-form Topics. Units never produce a Soft Error at all.

**Considered options:** Exact-unit matching only (rejected — a Student who converts correctly has done more work, not less, and would be marked wrong); folding units into a new `grading_policy` value (rejected — collides the moment an area answer is also a fraction); teaching `parse_to_fraction` to swallow units (rejected — it is shared by every Chapter, and `"5 kotów"` would silently parse as `5`); authoring every wrong-scale Unit as a per-Problem Trap (rejected — combinatorial, and the rule is fully general); accepting spelled-out Polish units (rejected — an unbounded natural-language surface for input no one types).

**Consequences:** The grader can now emit a Trap that has no `options_map` entry — new, and deliberate. It is authorized **for units only**; synthesizing Traps generally is a separate question, worth doing only where a rule is as mechanically detectable as this one. A units table maps dimension → (unit, factor) pairs, covering length (`mm cm dm m km`) and area (`mm² cm² dm² m² a ha km²`); volume is a later data addition, not a new branch, and is out of scope while the 2D ceiling holds. Unit matching is case- and whitespace-insensitive, and `cm2`/`cm^2` normalize to `cm²` rather than being penalized. Multiple-choice mode is untouched — it matches option strings and never reaches the parser. Angles are **not** part of this: `°` is never an `expected_unit`, angle is not a dimension in the table, and the symbol shown behind the input is a display-only `answer_suffix` the grader never reads.
