# Conversion-aware unit grading, with a grader-synthesized units Trap

Geometria Topics ask for answers that carry a Unit (`24 cm²`). Grading compares the Unit's **dimension** first, then converts same-dimension units to the Level's `expected_unit` before comparing magnitudes — so `0,0024 m²` is Correct for `24 cm²`. Where the converted value is wrong but the raw number is right (`24 m²`), the grader **synthesizes** a Trap on `converts_units_incorrectly` rather than requiring the generator to author every wrong unit.

**Decision:** A Level declares `expected_unit` (a length or area unit) in its curriculum YAML, separate from `grading_policy` — the two are orthogonal axes, notation-strictness and dimension. Splitting and normalizing the Unit happens in `grade()` *above* `parse_to_fraction`, never inside it. Omitting a Unit where one is expected is **Wrong**, not a Soft Error: on these Topics the Unit is part of the answer, exactly as form is on exact-form Topics. Units never produce a Soft Error at all. **Conversion resolves Correct before any Trap is considered**, and a wrong *dimension* short-circuits conversion entirely — there is no factor between `cm` and `cm²`, so a wrong-dimension answer can never convert to right. Trap matching therefore only ever sees answers already established as wrong, and `0,0024 m²` is Correct rather than a Trap that happens to match it (#210).

**Considered options:** Exact-unit matching only (rejected — a Student who converts correctly has done more work, not less, and would be marked wrong); folding units into a new `grading_policy` value (rejected — collides the moment an area answer is also a fraction); teaching `parse_to_fraction` to swallow units (rejected — it is shared by every Chapter, and `"5 kotów"` would silently parse as `5`); authoring every wrong-scale Unit as a per-Problem Trap (rejected — combinatorial, and the rule is fully general); accepting spelled-out Polish units (rejected — an unbounded natural-language surface for input no one types); putting Units in Radio options and asking authors to keep all four consistent (rejected — one slip makes the Unit the only thing a Student needs to read, and Input mode reuses the same `options_map`, so a Unit Trap cannot be authored for typing without also appearing as a button); passing the input mode into the generator so it can emit a different option set per mode (rejected — a repo-wide change to all 95 generators' contract, bought for one Chapter); suppressing Radio mode on unit-bearing Levels (rejected — Radio is what a Student at streak 0 is given precisely because they are struggling, and it is now the only place the app shows what a Unit-bearing answer looks like); declaring `expected_unit` per Problem from the generator (rejected — nothing needs a Unit that varies within a Level, and a YAML declaration is checkable at load time where generated option strings are not).

**Consequences:** The grader can now emit a Trap that has no `options_map` entry — new, and deliberate. It is authorized **for units only**; synthesizing Traps generally is a separate question, worth doing only where a rule is as mechanically detectable as this one. A units table maps dimension → (unit, factor) pairs, covering length (`mm cm dm m km`) and area (`mm² cm² dm² m² a ha km²`); volume is a later data addition, not a new branch, and is out of scope while the 2D ceiling holds. Unit matching is case- and whitespace-insensitive, and `cm2`/`cm^2` normalize to `cm²` rather than being penalized. Radio mode never carries a Unit in an option: a Problem's `correct` and every Trap and Filler are bare numbers, and the client appends `expected_unit` to all four buttons at render time, so the Student always reads `24 cm²` but the Unit can never be the discriminator (#213). `expected_unit` is therefore serialized to the client in Radio mode only — printing it beside the input would hand the Student the very distinction `labels_an_area_with_a_length_unit` exists to detect. Option strings still never reach the parser. Angles are **not** part of this: `°` is never an `expected_unit`, angle is not a dimension in the table, and the symbol shown behind the input is a display-only `answer_suffix` the grader never reads.

Because the declaration is per Level, a Level has exactly one `expected_unit`: `cm²` problems and `m²` problems are separate Levels. Generators stay entirely Unit-ignorant — they emit bare numbers and never see a Unit — so the loader can validate the declared Unit against the units table at load time, alongside the Trap-slug check. Nothing asks the Student for a Unit: the question prose does not mention it, and Radio mode is the only teacher of its form. That is fair rather than harsh because a penalized mistake resets streak to 0 and returns the Student to Radio, where all four options carry the Unit again (#213).
