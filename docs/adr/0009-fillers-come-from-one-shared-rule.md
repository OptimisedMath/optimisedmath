# Fillers come from one shared rule, not from each generator

Every Problem outside the comparison Levels shows four options, and any slot a Trap cannot take — skipped, or colliding with an option already taken (ADR-0008) — is filled by a Filler. We decided that `build_problem_dict` invents every Filler itself, from one rule keyed on the notation of the options on screen, and that generators stop passing `fillers`. Hand-written Filler formulas were the main source of collisions: measured over 500 rolls per generator, 45 of 96 generators fell short of four distinct options on some draws, mostly because an "answer + 1" formula recomputed an option already on screen (#283). A shared rule reached four options on every draw.

**The rule.** A Filler is a near miss of an option already on screen: its numerator, denominator or whole part moved by up to ±3, a decimal moved in its last decimal place, a whole number moved by up to ±3. Candidates are pooled from every Trap on screen and from the correct answer, and one is picked at random. A candidate keeps its source's shape — a mixed number stays mixed, a proper fraction proper, a fraction in lowest terms stays in lowest terms, a decimal keeps its number of decimal places — and is never negative where ADR-0007 applies. Where its source's notation would leave the correct answer the only option of its kind (a lone whole number among fractions), one Filler takes the correct answer's notation instead, so shape never gives the answer away.

**Two kinds of collision.** Authored options — the correct answer and the Traps — collide only when their strings are identical, because a Trap may differ from the correct answer in form alone (`stops_before_lowest_terms` offers ¹²⁄₁₅ beside ⁴⁄₅). A Filler has no intent to protect, so it must differ in value from everything on screen. When no candidate survives, the Problem is served one option short rather than discarded.

**Considered options:** Deriving Fillers from the correct answer alone (rejected — every Filler lands beside the right answer, and "pick the option nearest the others" found it on 47% of draws against 25% by chance; pooling Traps with the correct answer measured 33%); deriving only from Traps, falling back to the correct answer when none yields a candidate (measured 30.5%, rejected for giving less variety); one rule per Chapter (rejected — no Chapter needed different candidates, only different notations); a shared rule a generator's own `fillers` could supplement (rejected — it keeps the formulas that caused the collisions); moving only the numerator (rejected — over 40 generators then fall short of four options); walking deltas in a fixed order (rejected — varying the distractors is worth more, once the Problem's identity no longer includes its options).

**Consequences:** A generator may still pass `fillers=` explicitly, and that list replaces the rule — the escape hatch for options with no number to move (the comparison symbols) or a notation the rule cannot parse (`dec_to_frac_4`'s repeating decimals). A test pins which generators do, so an exemption cannot be added unnoticed. Because the same draw now shows different Fillers, `problem_fingerprint` identifies a Problem by its question and correct answer only, matching **Distinct Problem** in `CONTEXT.md`; hashing the options would let a repeat question past the session's dedupe.
