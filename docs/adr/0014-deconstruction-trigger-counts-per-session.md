# The Deconstruction trigger counts per Session, not per Level

A Deconstruction's trigger counted Misconception hits per (Session, Chapter, Topic, Level), so a Student who made the same error at two different Levels never accumulated a second hit and never got the walkthrough. **Decision:** the count is keyed on the Misconception slug alone and scoped to the Session — the second hit anywhere in the Curriculum fires the Deconstruction, and each Misconception is deconstructed at most once per Session. It lives on the Session's state, not in the telemetry table.

**Why the Level was never part of it.** A Misconception is defined as a believed rule "independent of any single Problem or Level" ([CONTEXT.md](../../CONTEXT.md)), walkthroughs are "authored per Misconception, not per Level or per Problem" ([ADR-0004](0004-deconstruction-outside-submission-cycle.md)), and [misconceptions.yaml](../../backend/data/misconceptions.yaml) only admits an entry to the deconstructable set if one fixed step sequence serves *every* Trap referencing it. The trigger was the one place that disagreed. `ignores_the_order_of_operations` already spans two Chapters and `operates_on_mixed_number_without_converting` five Topics; under the old key, a Student meeting either across Topics could never reach a second hit.

**Considered options:** key on (slug, Chapter) or (slug, Topic) — rejected, both reintroduce a curriculum-shaped boundary around a concept three other documents say has none. Re-key the telemetry query by id and keep it per Level — rejected, it fixes the display-name coupling but leaves the Level scope that is the actual defect. A dedicated hit-count table — rejected, a third home for Session-scoped data to buy an atomicity that the single-process, in-memory Session store does not need.

**Consequences:** the disarm guard had to move with the count. Left per Level, a Session-wide count would fire a fresh Deconstruction after a *single* hit at every subsequent Level, punishing the Student repeatedly for one wall — the outcome ADR-0004 exists to prevent. So the deconstructed set holds bare Misconception slugs, and the composite (Misconception, Level) key is deleted rather than moved: the trigger, the count and the Deconstruction's own ending now read one identity by construction. A game rule no longer reads the analytics table, so a telemetry schema change can no longer reset live game state, and no game rule is keyed on a Polish display name. The Session is now the only reset boundary, and the frontend starts a new Session on every page load — so a refresh between two hits loses the first. That is pre-existing behaviour of the deconstructed set and is decided separately.

**Amended by #383 — the progress reset is a second reset boundary.** The consequences above call the Session the only boundary at which the hit counts and the deconstructed set reset. That was written while every page load minted a new Session; [ADR-0019](0019-refresh-resumes-the-session.md) ended that, so a Session now lives for hours and the progress reset behind **Zresetuj cały postęp** is a boundary a Student actually reaches. `session_state.hard_reset` therefore clears `misconception_hits` and `deconstructed` alongside XP, the Chapter Frontiers, Selected, Streak and Flawless — the Session keeps its id, so Session identity is unchanged and the decision above stands: the count is still Session-scoped, and a Misconception is still deconstructed at most once per Session, counting from the reset. `reset_submission_cycle` still leaves both fields alone (#194) — moving away from a Problem is not a reset. A Deconstruction already running when the reset lands (`state.deconstruction`) is left running, outside #383's scope and decided separately.
