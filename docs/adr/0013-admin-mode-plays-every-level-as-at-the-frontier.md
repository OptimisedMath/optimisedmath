# Admin mode plays every Level as At the Frontier

Progression asked "is this Submission At the Frontier?" against the Admin's own stored Frontier, a record nothing else in Admin mode consults, so whether a Streak reset ever happened depended on where that Admin had once played as a Student (#304). We decided Admin mode answers that question with an unconditional yes: every Level an Admin plays behaves like a Student's Frontier Level — Streak fills to the Mastery threshold and resets, Level completion and Topic completion fire, XP and the Flawless bonus are earned in the Session — and the Admin write-back from #303 restores XP and Chapter Frontiers from the stored profile before anything reaches it.

**Considered options:** compare against the stored Frontier, as before (rejected — the one Level where QA sees a reset is an accident of that Admin's profile); compare against `chapter_max_frontier`, which `backend/docs/play-mode.md` rule 1 asks for everywhere else (rejected — an Admin would then see a reset only on the Chapter's last Level, so the Mastery cycle is effectively untestable); never reset an Admin's Streak (rejected — QA could not see the cycle at all); mirror only the completion flags and leave XP at zero (rejected — QA would watch an XP counter and a Flawless badge no Student ever sees).

**Consequences:** `PlayMode` answers At the Frontier alongside `resolve_frontier`, so the Student adapter delegates to the pure rule and the Admin adapter returns True. Progression keeps no play-mode branch: `_advance_streak_only` and `full_progression` go, `persists_profile` loses its last reader and goes with them, and an Admin's Session carries a moved Frontier that only the write-back restore ever reads. `play-mode.md` rule 1's "substitutes effective full unlock wherever a Frontier would be read" now describes Reachability alone, and progression is named as reading no Frontier at all. Post-Topic-completion Navigation stops routing through the effective Frontier and goes to the next Topic, which is what a Student was already getting.

**Amended — the restored set is XP and Chapter Frontiers ([#243](https://github.com/OptimisedMath/optimisedmath/issues/243), [ADR-0006](0006-profile-owns-selected-not-streak-or-flawless.md)).** As first written, the paragraph above named Streak among the fields the Admin write-back restores. There is nothing to restore it from. ADR-0006, recorded from #243 and closed 2026-09-12, dropped `users.streak` and ruled out a `flawless_eligible` column, so the profile holds XP, the three Selected fields and the Chapter Frontiers and nothing else — `_drop_stale_streak_column` in `backend/core/db.py` drops the retired column on schema init. Streak and Flawless are written from the Session into the stored Session (`sessions.state_json`) in both play modes, so nothing about them is play-mode-specific and nothing about them is restored. The decision, the considered options and the consequences above are untouched: an Admin still plays every Level as At the Frontier, and the Streak fill-and-reset this ADR decides on is exactly what the Session carries. #303's body was corrected to the same restored set, so #303 and its dependents #333 and #334 read consistently with this ADR.
